## 1. Overview &amp; Objectives

In Sprint 1, the custom application layer messaging protocol and the Game State Machine are designed before writing application code. Designing the protocol and FSM first establishes a disciplined blueprint that governs all subsequent software development.

**AI Policy:** Generic, unconstrained socket boilerplate generated by AI tools fails evaluation. This project therefore defines explicit message schemas and state transitions, and documents how AI assistants are prompted and constrained to adhere strictly to the custom protocol blueprint.

## 2. Game

A two-player **Tic-Tac-Toe** game (3×3 board) played over TCP: one server process hosts a game room; two clients connect with player aliases, take turns submitting moves, and the server validates moves, broadcasts state, and declares the outcome (win / draw / forfeit).

## 4. Deliverable Summaries

### 4.1 `protocol_blueprint.md` — Application Protocol Blueprint (TTT-1)

- **Transport:** TCP; **serialization:** UTF-8 JSON.
- **Framing rule:** newline-delimited JSON (`0x0A` terminator) with a documented stream buffer receiver algorithm that handles coalescing and fragmentation, plus raw wire stream examples and JSON Schemas.
- **8 message types** — CONNECT, LOBBY\_WAIT, GAME\_START, MOVE, STATE\_UPDATE, ERROR, DISCONNECT, GAME\_OVER — each with exact field specifications, data types, constraints, and error codes (`OUT_OF_TURN`, `INVALID_MOVE`, `MALFORMED_JSON`, …).
- **Connection termination logic:** three documented paths, the exact exception set to catch, and a per path cleanup checklist.

### 4.2 `fsm_specification.md` — Game State Machine Specification

- Six state server FSM: INIT → WAITING\_FOR\_PLAYERS → GAME\_START → PLAYER\_TURN → EVALUATE\_MOVE → GAME\_OVER (→ reset).
- Full transition table with guards, actions, and next states.
- Mermaid `stateDiagram-v2` diagrams for the server FSM and a simplified client FSM, rendered natively on GitHub.
- Edge cases specified: out of turn moves, invalid payloads, malformed JSON, occupied cells, and unexpected client disconnects.

### 4.3 `ai_prompts.md` — AI Prompting &amp; Constraint Strategy

- The system prompt used in all AI coding sessions: schema first, framing first, interface first, with the literal wire example as a byte level oracle.
- Task level prompts for the frame encoder, buffered frame decoder, FSM dispatcher, and disconnect handling loop, each tied to a spec clause.
- Verification workflow and a banned anti patterns table.
